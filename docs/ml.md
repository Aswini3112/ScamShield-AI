# ScamShield AI — ML Pipeline Documentation

> **Important disclaimer:** All training data used in this prototype is **synthetic** and generated programmatically. Evaluation metrics reflect performance on a synthetic test set only. They do **not** represent real-world scam detection effectiveness. Do not use these numbers to make claims about production-level accuracy.

---

## 1. Dataset

### Source
Synthetic, generated by `ml/src/generate_dataset.py`.

### Structure
```
ml/data/raw/scam_dataset.csv
  Columns: text, label, category

Labels:
  0 = SAFE       (legitimate messages)
  1 = SUSPICIOUS (borderline content)
  2 = SCAM       (confirmed scam patterns)
```

### Composition (~530 raw samples, ~281 after deduplication)
| Split | SAFE | SUSPICIOUS | SCAM |
|---|---|---|---|
| Train (80%) | 51 | 19 | 154 |
| Test (20%) | 13 | 5 | 39 |

### Scam categories covered
- Banking/KYC Scam
- UPI/Payment Scam
- Job/Recruitment Scam
- Investment Scam
- Delivery/Courier Scam
- Government Impersonation
- Customer Support Scam
- Social Media Scam
- QR Scam
- Tamil-language scams
- Tanglish-language scams

### Generation approach
Template strings with `{bank}`, `{url}`, `{amount}` placeholders filled with generic values (e.g. "Example Bank", "Example Courier"). Each template is filled multiple times with different random values to create variation.

## 2. Feature Engineering

### Text features (`app/ml/feature_extractor.py`)
35+ numeric/boolean features extracted from raw text:

**Structural features**
| Feature | Description |
|---|---|
| `text_length` | Character count |
| `word_count` | Word count |
| `capitalisation_ratio` | Ratio of uppercase chars |
| `exclamation_count` | Number of `!` characters |
| `url_count` | Number of URLs detected |
| `phone_count` | Number of phone numbers |
| `currency_mention_count` | Rs./INR/₹ + amount patterns |

**Keyword scores** (count of keyword matches)
| Feature | Keywords matched |
|---|---|
| `urgency_score` | immediately, urgent, today, hurry, deadline… |
| `fear_score` | block, suspend, arrest, penalty, freeze… |
| `threat_score` | failure to, consequences, prosecuted… |
| `payment_score` | pay, upi, transfer, neft, rs., ₹… |
| `otp_score` | otp, one time password, verification code… |
| `credential_score` | aadhaar, pan card, account number, cvv… |
| `reward_score` | congratulations, winner, prize, selected… |
| `impersonation_score` | bank, rbi, income tax, police, government… |
| `job_score` | work from home, earn per month, wfh… |
| `investment_score` | invest, returns, profit, trading, crypto… |
| `kyc_score` | kyc, know your customer, kyc update… |
| `qr_score` | scan qr, qr code, scan to receive… |
| `cta_score` | click here, visit the link, download app… |

**Boolean indicators** (1/0)
`has_urgency`, `has_fear`, `has_payment`, `has_credential_request`, `has_impersonation`, `has_reward`, `has_suspicious_url`, `has_job_offer`, `has_investment`, `has_kyc`, `has_qr`, `has_shortener`

### URL features
| Feature | Description |
|---|---|
| `url_length` | Full URL length |
| `has_https` | HTTPS protocol |
| `has_ip_address` | IP instead of domain name |
| `is_url_shortener` | Known shortener domain |
| `has_suspicious_tld` | .xyz, .tk, .ml, .ga, .cf… |
| `subdomain_count` | Number of subdomains |
| `has_encoded_chars` | `%` in URL |
| `path_depth` | `/` depth in path |
| `has_suspicious_keywords` | login, verify, kyc, otp in URL |

## 3. Preprocessing (`ml/src/preprocess.py`)

1. Remove rows with null `text` or `label`
2. Apply `clean_text()`:
   - Lowercase
   - Replace URLs with `URLTOKEN`
   - Replace phone numbers with `PHONETOKEN`
   - Replace currency amounts with `AMOUNTTOKEN`
   - Collapse whitespace
3. Deduplicate on cleaned text
4. Stratified 80/20 train/test split (seed=42)

---

## 4. Model Architecture

### Combined feature vector
```
cleaned_text → TF-IDF (5000 features, 1-2 ngrams, sublinear_tf=True)
                     ↕ hstack
numeric features (35 features)
─────────────────────────────
Total feature vector: ~1096 dimensions
```

### Models trained and compared
| Model | Config |
|---|---|
| Logistic Regression | C=5.0, multinomial, balanced class weights |
| Random Forest | 200 trees, max_depth=20, balanced |
| XGBoost | 200 estimators, lr=0.1, max_depth=6 |

## 6. Risk Scoring

The final risk score is a blend of:
- ML model probability: `P(SCAM) * 0.6 + P(SUSPICIOUS) * 0.3`
- Rule-based score: `* 0.1`

**Risk bands** (prototype thresholds — not scientifically calibrated):
| Score | Level | Interpretation |
|---|---|---|
| 0–29 | LOW | Appears mostly safe |
| 30–59 | MEDIUM | Some suspicious patterns |
| 60–79 | HIGH | Strong scam indicators |
| 80–100 | CRITICAL | Very high scam confidence |

## 8. Rule-Based Fallback

If `model.joblib` is missing, `predictor.py` falls back to a deterministic rule-based scorer. This ensures the application works before training.

The rule score is computed by weighted sum of keyword feature counts, e.g.:
- `urgency_score * 10` (up to +25)
- `fear_score * 8` (up to +20)
- `has_credential_request * 15`
- `has_suspicious_url * 15`
- etc.

---

## 9. Limitations

- Training data is synthetic — real-world scams are far more varied
- No real threat intelligence or URL reputation data
- Tamil/Tanglish support relies on keyword matching only
- Small dataset (~281 unique samples) — model may overfit
- Novel scam types not present in training data will score lower
- No adversarial robustness testing

## 10. Reproduce Training

```bash
# Generate synthetic data
python ml/src/generate_dataset.py

# Preprocess
python ml/src/preprocess.py

# Extract features
python ml/src/feature_engineering.py

# Train all models, pick best, save artifacts
python ml/src/train.py

# Evaluate saved model
python ml/src/evaluate.py

# CLI prediction test
python ml/src/predict.py "Your account will be blocked. Click now."
```
